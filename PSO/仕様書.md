# ばんさばん (Vansav) 仕様書

本ドキュメントは、本作「ばんさばん（Vansav）」のゲーム仕様およびプログラムアーキテクチャをまとめた仕様書です。次期プロジェクトのベースラインや設計資料として活用してください。

---

## 1. 概要
- **ジャンル**: 見下ろし型サバイバルアクション（Vampire Survivors ライク）
- **プラットフォーム**: Webブラウザ（PC / スマートフォン対応）
- **プレイ人数**: 1人 〜 2人（ローカルマルチプレイ対応）
- **画面解像度**: ベース解像度 640x360（Canvas内でスケールして全画面表示）

## 2. ゲーム仕様

### 2.1. ゲームサイクル
1. キャラクターを選択し、ゲームを開始。
2. 時間経過とともに迫りくる大量の敵を倒し、経験値（クリスタル）を獲得。
3. レベルアップにより装備（攻撃アイテム、補助アイテム）を取得・強化。
4. **20分（1200秒）** 生き残り、出現するすべてのボスを撃破すればゲームクリア（Complete）。
5. 途中でHPが0になり倒れるか、クリアした時点でリザルト画面へ。獲得した「コイン」はセーブデータに保存される。
6. 集めたコインを消費して、ショップで基本ステータスの永続強化や、新キャラクター・新アイテムの解放を行う。

### 2.2. キャラクターシステム
- **ステータス**: HP、こうげき、ぼうぎょ、すばやさ、うんのよさ の5種類。
- **所持枠制限**: キャラクターごとに攻撃アイテム（`maxAtk`）と補助アイテム（`maxBuf`）の所持上限枠が設定されている。
- **初期装備**: キャラクターごとにゲーム開始時から所持している固有の攻撃アイテム（`initialEquip`）が存在。
- **解放条件**: 特定のキャラクターでクリアするなどの条件を満たすと、ショップのラインナップに並び、コインで購入することで使用可能になる。

### 2.3. 出現スケジュール（ウェーブ）
- **通常敵**: `ENEMY_WAVES` テーブルに基づき、時間帯ごとに設定された敵テーブルからランダム（ウェイト抽選）で出現する。出現間隔も時間帯によって変化する。
- **ボス**: 5分、10分、15分に巨大なボス（ドン・メデューサ）が出現。
- **レアモンスター（宝箱）**: 4分、8分、12分、16分に確定で出現。倒すと宝箱（アイテムボックス）をドロップする。出現タイミングが遅いほど、HPと防御力に補正がかかり強くなる。

### 2.4. アイテムとレベルアップ
- 敵を倒すと経験値（大・中・小など）をドロップ。取得してゲージが溜まるとレベルアップ。
- レベルアップ時には、未所持のアイテムまたは所持済みのアイテムのレベルアップ候補がランダムに提示される（通常2択、スキル「エクストラロール」で3択になる確率上昇）。
- 「リロール」機能を消費することで、候補を引き直すことが可能。
- **宝箱**: レアモンスターが落とす宝箱を拾うと、スロット演出とともに所持中のアイテムがランダムにレベルアップする（運の良さによって複数レベルアップする確率が変動）。

## 3. プログラム仕様

### 3.1. ファイル構成
- `vansav.html`: ゲームのメイン画面、UIレイヤー（タイトル、ショップ、ポーズ、リザルト等）のDOM定義。
- `vansav_game.js`: メインのゲームロジック、描画処理、データ定義を含むコアスクリプト。
- `assets.json`: ドット絵のカラーパレットおよびピクセルデータ（8x8ベースの文字列配列）を定義。
- `tori_se.js` / `tori_music.js` 等: 効果音・BGMの再生制御。

### 3.2. 主要なデータ構造と定数
- `SAVE_DATA`: `localStorage` に `vansav_save` として保存される。コイン所持数、永続強化レベル、キャラやアイテムの解放フラグ、クリアフラグを管理。
- `GAME` オブジェクト: ゲームの実行状態（現在時刻、モード、各種エンティティの配列）を管理するシングルトン的なオブジェクト。
- `CHARACTERS` 配列: 登場キャラクターのマスターデータ。
- `EQUIP_DATA` オブジェクト: 攻撃（`atk`）および補助（`buf`）アイテムのマスターデータ。最大レベル、クールダウン、ダメージ倍率、固有の挙動ロジックを持つ。

### 3.3. エンティティとクラス設計
- `Player` クラス: プレイヤーの座標、ステータス、所持装備、無敵時間、入力に応じた移動処理を管理。
- `Enemy` クラス: 敵キャラクター。プレイヤーへの追従ロジック（A*などの複雑な経路探索はなく、対象プレイヤーへ向かって直進する）、ノックバック、被ダメージ処理を管理。
- `Item` クラス: フィールドに落ちている経験値、コイン、宝箱などのドロップアイテム。
- `Projectile` クラス: 魔法弾、ファイアボール、ブーメランなどの飛び道具。座標更新、敵との当たり判定処理を持つ。
- `Particle` / `DamageText` クラス: 爆発エフェクトやダメージ数値のポップアップ描画を担当。

### 3.4. メインループと描画アーキテクチャ
- **ゲームループ**: `requestAnimationFrame` を用いた `gameLoop()` 関数により、毎フレーム `updateGame()` と `drawGame()` が呼び出される。
- **描画 (`drawGame`)**: HTML5 Canvas の 2D Context を使用。
  - カメラ（画面の中心座標）は、1Pプレイ時はプレイヤー中心、2Pプレイ時は2人の中間座標を計算して追従する。
  - タイルベースの背景、ドロップアイテム、敵、プレイヤー、エフェクト、UIの順に描画（z-index相当）。
- **事前レンダリング (`preRenderSprites`)**: `assets.json` で定義されたピクセルデータは、起動時にオフスクリーンCanvasへ描画して `PRE_RENDERED` オブジェクトにキャッシュし、描画パフォーマンスを最適化している。

### 3.5. 当たり判定（コリジョン）
- 基本的に矩形同士の AABB (Axis-Aligned Bounding Box) または、中心点からの距離ベースの円形判定を用いた軽量な処理を実装。
- 敵の数が膨大になるため、毎フレーム全検索するのではなく、一定の簡略化や間引き処理（※現状はO(N^2)に近い処理もあるため、次作でのクォードツリー等導入による最適化余地あり）。

### 3.6. UI制御と画面遷移
- HTMLの `div` 要素（`.screen` クラス）を利用し、JavaScript側から `setMode('title' | 'game' | 'levelup' | 'shop' | 'result' | 'chest' | 'pause')` を呼び出すことで `display` プロパティを切り替えて画面遷移を実現。
- ゲームプレイ中のHUD（HPバーや経験値バー、タイマー）のみCanvasの上にオーバーレイ表示される。
